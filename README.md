# FAPI 账号互通

将 QQ 用户与 TokenRouter 用户建立一对一绑定，并提供余额查询、每日签到、排行榜、插件账单、QQ群余额红包和打劫。支持 OneBot 与 QQ 官方机器人；普通业务操作限制在管理员配置的指定群，管理操作限制为 AstrBot 管理员私聊。绑定、奖励和游戏结算状态存储在远程 MySQL。

## 指令

```text
/fapi help
/fapi 帮助
/fapi 菜单
/fapi 绑定
/fapi 绑定 <完整邮箱>
/fapi 绑定状态
/fapi 解绑 [确认]
/fapi 余额
/fapi 签到
/fapi 签到排行
/fapi 红包 <总金额> <份数>
/fapi 抢红包 [红包编号]
/fapi 红包状态 [红包编号]
/fapi 红包排行
/fapi 账单
/fapi 打劫 @用户
/fapi 打结 @用户
/fapi 管理
```

`help`、`帮助` 和 `菜单` 是同一个功能，会按当前 QQ 平台显示适用的绑定方式和红包创建权限。

除管理员私聊入口外，所有指令只能在 `allowed_group_id` 指定的群中使用，私聊和其他群会在访问 TokenRouter 或 MySQL 前被拒绝。OneBot 中，`红包` 可由群主、群管理员或 AstrBot 管理员创建；QQ 官方机器人无法可靠读取群角色，因此只允许 AstrBot 管理员创建。`抢红包` 不填写编号时领取指定群最新的可用红包。

`/fapi 管理` 是唯一例外：它只允许 AstrBot 管理员在 QQ 私聊中使用，群聊管理员也会被拒绝。普通用户私聊不会访问 TokenRouter。支持：

```text
/fapi 管理 概览
/fapi 管理 RPM [邮箱]
/fapi 管理 排行 [数量]
/fapi 管理 状态 <邮箱>
/fapi 管理 账单 <邮箱>
/fapi 管理 未完成任务 [数量]
/fapi 管理 重试 <任务编号>
/fapi 管理 加余额 <邮箱> <金额>
/fapi 管理 减余额 <邮箱> <金额>
```

`概览` 显示中转站今日累计数据和近 5 分钟 RPM/TPM。`RPM` 不填写邮箱时显示全站吞吐，填写邮箱时显示该用户当前分钟 RPM 与分组限额。`排行` 按 `reward_timezone` 查询今日消费，默认 10 人、最多 20 人；上游排行接口不返回邮箱，因此这里只显示用户名和用户 ID，用户名不参与任何身份识别。`查询` 仍可作为 `状态` 的兼容别名。

`未完成任务` 同时列出待补发奖励、待结算游戏和人工退款任务。`重试` 只把原任务重新放回补偿队列，沿用固定兑换码或幂等键；已经完成的任务会被拒绝，不能借此重复发放余额。

管理员用户查询、RPM 查询和余额调整均按唯一邮箱精确定位。邮箱必须完全一致且结果唯一。余额写操作使用消息 ID 生成固定幂等键；无法取得消息 ID 时拒绝调账，网络异常导致结果不确定时也不会自动换键重试。

## 游戏规则

- `打劫` 必须结构化 `@` 一名其他群成员，发起者和目标都必须已经绑定。`打结` 是同一命令的别名。
- 打劫成功时按后台金额从目标余额扣除，并把同额余额加入发起者账户。默认每次 `USD 0.10`、成功率 30%、冷却 300 秒。
- 打劫失败后可触发反噬，从发起者扣款并转给目标。默认开启，失败后反噬率 20%、金额 `USD 0.05`；因此默认总体反噬概率为 `(1 - 30%) × 20% = 14%`。发起者余额不足时不会给目标入账，但本次仍消耗冷却。
- 余额不足由 TokenRouter 的原子扣款接口判定，不使用“先查余额再扣款”。同一消息使用固定幂等键，重复投递不会重复扣款或派奖。
- 网络异常时结算任务会后台重试。扣款完成但派奖发生明确错误时，系统会自动退款；不会把半完成转账直接标记为失败。
- 多实例通过 MySQL 租约竞争同一笔结算，未取得租约的实例不会调用余额接口。永久退款错误达到重试上限后会停止自动重试并记录人工处理日志。

## 绑定规则

- OneBot 使用 `/fapi 绑定` 时自动查询发送者的 `<QQ号>@qq.com`，也可使用 `/fapi 绑定 <完整邮箱>`。
- QQ 官方机器人无法取得真实 QQ 号，必须使用 `/fapi 绑定 <完整邮箱>`。
- 绑定只按唯一邮箱精确查询，用户名不参与身份识别；内部仍保存 TokenRouter 用户 ID 作为稳定关联键。
- 一个 QQ 只能绑定一个 TokenRouter 用户，一个 TokenRouter 用户也只能绑定一个 QQ。
- 邮箱不存在或查询结果不唯一时不会写入绑定。
- `/fapi 解绑` 需要在 60 秒内再次发送 `/fapi 解绑 确认`。解绑后的重新绑定冷却默认 1 小时，并持久化到 MySQL。

主动填写邮箱的绑定命令会出现在群消息中。余额查询仅回显脱敏邮箱；仍应确保指定群是受控群，并按需清理包含完整邮箱的绑定消息。

## 奖励规则

- 签到按 `reward_timezone` 的自然日计算，同一 QQ 和同一 TokenRouter 用户每天都只能领取一次。
- 默认签到奖励会在 `USD 0.01` 至 `USD 0.10` 之间按分随机，签到每日总预算为 `USD 10.00`。
- 默认单个红包不超过 `$20.00`、100 份，红包每日总预算为 `$100.00`，有效期 60 分钟。
- 每份红包至少 `$0.01`。金额使用 8 位小数整数精度拆分，最后一份获得全部剩余金额。
- 红包预算在创建时按总金额预留，过期未领取部分不会返还到当天预算。
- 发奖失败或响应结果不确定时，任务会后台重试；固定兑换码保证同一任务不会因重试重复加余额。

奖励通过 TokenRouter 的“创建并兑换”管理接口发放。若站点开启邀请返利，余额兑换可能同时给领取者的邀请人计提返利；每日预算只限制发给签到者和红包领取者的金额，不包含这部分额外返利。无需邀请返利时，应在 TokenRouter 中关闭该功能。不要删除以 `FAPIR_` 开头的奖励兑换码，否则会破坏跨故障重试的永久去重依据。

## 配置

在 AstrBot WebUI 中配置：

- `allowed_group_id`：OneBot 填数字群号；QQ 官方机器人填 AstrBot 事件中的群 `group_openid`。留空时所有业务指令默认拒绝。
- TokenRouter 根地址和管理员 API Key。地址不要带 `/api/v1`；API Key 必须有用户查询、余额调整及奖励码创建兑换权限。
- 管理员私聊开关和单次调账金额上限；默认开启，单次最多 `USD 1,000.00`。
- 远程 MySQL 地址、端口、用户名、密码、数据库和 TLS 设置。
- 签到奖励最小值与最大值、签到每日预算、红包上限、红包每日预算、份数、有效期和奖励时区。
- 打劫开关、金额、成功率、冷却，以及反噬开关、失败后反噬率和反噬金额。
- 解绑后的重新绑定冷却秒数；设为 0 可关闭。
- 可选的每日播报开关、完整群 UMO 和播报时间。UMO 可在目标群发送 `/sid` 获取，必须与 `allowed_group_id` 指向同一群。
- 绑定表、绑定冷却表、五张奖励表、每日播报状态表、游戏结算表及游戏冷却表的表名。十张表名必须互不重复，只能包含字母、数字和下划线，且必须以字母开头。

MySQL 用户至少需要目标数据库的 `CREATE`、`ALTER`、`SELECT`、`INSERT`、`UPDATE` 权限。插件启动时会自动创建：

```text
astrbot_fapi_bindings
astrbot_fapi_binding_cooldowns
astrbot_fapi_reward_jobs
astrbot_fapi_checkins
astrbot_fapi_red_packets
astrbot_fapi_red_claims
astrbot_fapi_reward_budgets
astrbot_fapi_daily_broadcasts
astrbot_fapi_game_operations
astrbot_fapi_game_cooldowns
```

MySQL 会话由插件固定为 UTC，不需要修改服务器全局时区。插件启动时数据库暂时不可用会自动继续重连；出现“退款已转人工处理”日志时，应先在 TokenRouter 核对对应幂等键和用户余额，再使用管理员任务重试，不能直接改成已退款。

远程 MySQL 建议启用 TLS 和证书验证。管理员 API Key 能查询用户并调整真实余额，应只保存在 AstrBot 插件配置中。

## 安装与升级

插件仓库：<https://github.com/18848298290-del/astrbot_plugin_fapi>

### 当前 ZIP 安装迁移到 GitHub 更新

当前版本如果是通过 ZIP 上传安装，AstrBot 会把安装来源记录为 `upload`，不会仅凭 `metadata.yaml` 中的 `repo` 自动启用更新。只需迁移一次：

1. 打开 AstrBot 管理面板的“插件 → 已安装”。
2. 找到“FAPI 账号互通”，选择“更换插件源”。
3. 选择“直接使用仓库地址”，确认仓库为上面的 GitHub 地址，然后保存。
4. 以后在同一插件卡片上点击“更新”即可拉取 GitHub `main` 分支的最新代码。

如果当前管理面板没有“更换插件源”，卸载插件时不要勾选删除插件配置和持久化数据，然后点击“安装插件（+）→ 从链接安装”，填入上面的 GitHub 仓库地址。完成这一次安装后，后续不再需要上传 ZIP。

### 以后发布新版

每次发布时同步修改 `metadata.yaml` 和 `main.py` 中的版本号，并在 `CHANGELOG.md` 记录变更，然后将代码推送到 GitHub `main` 分支。AstrBot 的仓库更新直接下载默认分支最新代码，不要求创建 GitHub Release，也不要求提交到 AstrBot 插件市场。

仓库根目录必须继续保留 `main.py`、`metadata.yaml`、`requirements.txt` 等插件文件，不能在仓库内再套一层插件目录。

升级不会删除原绑定表。3.1.0 会按需将旧表中的 QQ 号、OpenID 和群 ID 字段扩容为 128 字符，并改为区分大小写的二进制排序规则；数据库用户需要 `ALTER` 权限。

个人机器人旧绑定使用数字 QQ，官机使用成员 OpenID，二者无法自动证明属于同一人。已有用户在官机重绑同一中转站账号时会保持原绑定并提示冲突，需要管理员核验后在绑定表中迁移或解除旧记录；插件不会仅凭公开的用户名和邮箱自动覆盖绑定。
