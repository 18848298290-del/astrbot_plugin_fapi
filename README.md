# FAPI 账号互通

将 QQ 用户与 TokenRouter 用户建立一对一绑定，并提供余额查询、每日签到和 QQ 群余额红包。支持 OneBot 与 QQ 官方机器人，所有操作只能在管理员配置的指定群中执行；绑定及奖励状态存储在远程 MySQL。

## 指令

```text
/fapi help
/fapi 帮助
/fapi 菜单
/fapi 绑定
/fapi 绑定 <用户名>
/fapi 绑定 <用户名> <完整邮箱>
/fapi 绑定状态
/fapi 余额
/fapi 签到
/fapi 红包 <总金额> <份数>
/fapi 抢红包 [红包编号]
/fapi 红包状态 [红包编号]
```

`help`、`帮助` 和 `菜单` 是同一个功能，会按当前 QQ 平台显示适用的绑定方式和红包创建权限。

所有指令只能在 `allowed_group_id` 指定的群中使用，私聊和其他群会在访问 TokenRouter 或 MySQL 前被拒绝。OneBot 中，`红包` 可由群主、群管理员或 AstrBot 管理员创建；QQ 官方机器人无法可靠读取群角色，因此只允许 AstrBot 管理员创建。`抢红包` 不填写编号时领取指定群最新的可用红包。

## 绑定规则

- OneBot 可用 `/fapi 绑定 <用户名>`：用户名必须完全一致，且该用户邮箱必须是发送者的 `<QQ号>@qq.com`。
- QQ 官方机器人无法取得真实 QQ 号，必须使用 `/fapi 绑定 <用户名> <完整邮箱>`。
- `/fapi 绑定 <用户名> <完整邮箱>`：用户名和邮箱必须同时完全匹配同一个 TokenRouter 用户。
- 一个 QQ 只能绑定一个 TokenRouter 用户，一个 TokenRouter 用户也只能绑定一个 QQ。
- 用户名、邮箱不匹配或查询结果不唯一时不会写入绑定。

绑定命令会把完整邮箱发送到群消息中。请确保指定群是受控群，并按需清理包含邮箱的消息记录。

## 奖励规则

- 签到按 `reward_timezone` 的自然日计算，同一 QQ 和同一 TokenRouter 用户每天都只能领取一次。
- 默认签到奖励为 `$0.05`，签到每日总预算为 `$10.00`。
- 默认单个红包不超过 `$20.00`、100 份，红包每日总预算为 `$100.00`，有效期 60 分钟。
- 每份红包至少 `$0.01`。金额使用 8 位小数整数精度拆分，最后一份获得全部剩余金额。
- 红包预算在创建时按总金额预留，过期未领取部分不会返还到当天预算。
- 发奖失败或响应结果不确定时，任务会后台重试；固定兑换码保证同一任务不会因重试重复加余额。

奖励通过 TokenRouter 的“创建并兑换”管理接口发放。若站点开启邀请返利，余额兑换可能同时给领取者的邀请人计提返利；每日预算只限制发给签到者和红包领取者的金额，不包含这部分额外返利。无需邀请返利时，应在 TokenRouter 中关闭该功能。不要删除以 `FAPIR_` 开头的奖励兑换码，否则会破坏跨故障重试的永久去重依据。

## 配置

在 AstrBot WebUI 中配置：

- `allowed_group_id`：OneBot 填数字群号；QQ 官方机器人填 AstrBot 事件中的群 `group_openid`。留空时所有业务指令默认拒绝。
- TokenRouter 根地址和管理员 API Key。地址不要带 `/api/v1`。
- 远程 MySQL 地址、端口、用户名、密码、数据库和 TLS 设置。
- 签到金额、签到每日预算、红包上限、红包每日预算、份数、有效期和奖励时区。
- 绑定表及五张奖励表的表名。表名只能包含字母、数字和下划线，且必须以字母开头。

MySQL 用户至少需要目标数据库的 `CREATE`、`ALTER`、`SELECT`、`INSERT`、`UPDATE` 权限。插件启动时会自动创建：

```text
astrbot_fapi_bindings
astrbot_fapi_reward_jobs
astrbot_fapi_checkins
astrbot_fapi_red_packets
astrbot_fapi_red_claims
astrbot_fapi_reward_budgets
```

远程 MySQL 建议启用 TLS 和证书验证。管理员 API Key 能查询用户并发放真实余额，应只保存在 AstrBot 插件配置中。

## 安装与升级

上传 `astrbot_plugin_fapi.zip`。如果 AstrBot 提示 `目录 astrbot_plugin_fapi 已存在`，请先在插件管理页卸载旧版本，再上传新版；上传安装不会自动覆盖同名目录。

升级不会删除原绑定表。3.1.0 会按需将旧表中的 QQ 号、OpenID 和群 ID 字段扩容为 128 字符，并改为区分大小写的二进制排序规则；数据库用户需要 `ALTER` 权限。

个人机器人旧绑定使用数字 QQ，官机使用成员 OpenID，二者无法自动证明属于同一人。已有用户在官机重绑同一中转站账号时会保持原绑定并提示冲突，需要管理员核验后在绑定表中迁移或解除旧记录；插件不会仅凭公开的用户名和邮箱自动覆盖绑定。
